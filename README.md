# Портфолио vlddvr — каркас сайта

Статический сайт без фреймворков. Все страницы генерируются Node-скриптом `build.js`
из данных в `data/`. Руками правятся только данные, CSS-токены и шаблоны в `build.js`.

## Структура

```
data/
  site.json       — контакты, PUBLIC-флаг, baseUrl
  taxonomy.json   — направления и их ответвления (branches), группы тегов
                    (копия из ../taxonomy.json, этот файл не редактировать,
                    а менять именно site/data/taxonomy.json)
  projects.json   — кейсы (контент сайта)
assets/
  css/style.css   — токены (:root) + вёрстка, mobile-first
  js/main.js      — лайтбокс, двухуровневый фильтр, появление при прокрутке
  img/placeholder — SVG-плейсхолдеры обложек, превью, аватара
  files/          — файлы для скачивания (например, PDF брендбуков)
build.js          — генератор страниц
check-links.js    — проверка относительных ссылок на битые
index.html, about.html, projects/<slug>.html       — RU (генерируется)
en/index.html, en/about.html, en/projects/<slug>.html — EN (генерируется)
directions/<id>.html, en/directions/<id>.html       — страницы направлений (генерируется)
robots.txt         — генерируется
sitemap.xml         — генерируется только при PUBLIC = true
```

## Как собрать

```
"C:\Program Files\nodejs\node.exe" build.js
"C:\Program Files\nodejs\node.exe" check-links.js
```

Второй скрипт проверяет все относительные `href`/`src` на всех сгенерированных
страницах (включая `/en/`) и завершается с ошибкой, если есть битые ссылки или
абсолютный путь с ведущим `/`.

## Как добавить кейс

1. Добавить объект в `data/projects.json`. Обязательные поля:
   - `slug` — латиницей, уникальный, используется в URL;
   - `title.ru` / `title.en`, `client`, `summary.ru/en`;
   - `directions[]` — id из `data/taxonomy.json` (`branding`, `3d`, `motion`, `print`, `web`, `ai-fashion`);
   - `branches[]` — id ответвлений внутри направлений (например `logo`, `stands`); ответвление
     без единого кейса на сайте не показывается — фильтр и страница направления строятся
     автоматически только из того, что реально есть;
   - `tags.industry/format/tools/region/lang` — массивы id/строк (industry и format — id из
     `taxonomy.json`, остальные можно как строки);
   - `task` / `approach` / `result` — объекты `{ru, en}` или `null`, если блока пока нет
     (на странице кейса такой блок просто не выводится — не выдумывать текст);
   - `cover` — `{src, w, h, alt:{ru,en}, focus?}`; `w`/`h` обязательны и должны быть настоящими —
     по ним строится пропорция кадра (работы на сайте не обрезаются). Необязательное `focus`
     (например `"60% 40%"`, по умолчанию центр) — точка фокуса для единственных мест, где
     кадр обрезается: hero на главной, шапка кейса и крупный кадр «следующий кейс»;
   - `behance` — ссылка или `null`;
   - `personal` — необязательно, `true` для личных проектов (метка «Личный проект / Personal project»);
   - `aiContent` — `true`, если в работе использовался ИИ (на сайте появляется метка
     «Сделано с ИИ / Made with AI»);
   - `order` — число, определяет порядок в сетке и «следующий кейс»;
   - `featured` — `true` у одного кейса, который показывается в hero на главной;
   - `blocks[]` — произвольный набор блоков в нужном порядке, типы:
     - `images` — `{type:"images", images:[{src,w,h,alt}]}` — сетка с лайтбоксом;
     - `pdf` — `{type:"pdf", file, pages:[{src,w,h,alt}]}` — превью страниц + ссылка на файл;
     - `video` — `{type:"video", poster, src|null, embed|null, caption}` — свой файл,
       встраивание YouTube/Vimeo (`embed` — ссылка для iframe) или просто постер;
     - `embed` — `{type:"embed", url, label, caption}` — живое демо в iframe + кнопка «Открыть»;
     - `sketchfab` — `{type:"sketchfab", modelId, title}` — iframe модели по id;
     - `text` — `{type:"text", text:{ru,en}}`.
2. Положить изображения/файлы в `assets/img/...` или `assets/files/...` (пути в JSON —
   относительные от корня сайта, без ведущего `/`).
3. Запустить `node build.js`, затем `node check-links.js`.

## Направления и ответвления

Источник правды — `data/taxonomy.json` (копия `../taxonomy.json`, не трогать оригинал).
Направление с `"hidden": true` (сейчас это `ai-fashion`) не появляется на сайте вообще,
даже если у него есть кейсы. Ответвление показывается в фильтре и на странице направления
только если хотя бы один кейс одновременно указывает это направление в `directions[]` и
это ответвление в `branches[]`.

Фильтр на главной — двухуровневый: направление → чипы ответвлений. Состояние фильтра
отражается в хэше адреса (`#3d/stands`, `#print`, `#industry/auto`), такую ссылку можно
скопировать и отправить — страница откроется с уже применённым фильтром.

## Как разблокировать (сделать сайт публичным)

Сейчас `data/site.json` → `"PUBLIC": false`. Это значит:
- на каждой странице `<meta name="robots" content="noindex, nofollow">`;
- `robots.txt` содержит `Disallow: /`;
- `sitemap.xml` не генерируется;
- Open Graph-теги не выводятся.

Чтобы открыть сайт для поиска и соцсетей:
1. Поставить `"PUBLIC": true` в `data/site.json`.
2. Запустить `node build.js` — появится `sitemap.xml`, `robots.txt` разрешит индексацию,
   на страницах появятся Open Graph-теги с абсолютными ссылками на `baseUrl`.
3. Закоммитить и задеплоить.

Разблокировку делает только пользователь или агент по его прямой команде — см. `decisions.md`
в корне проекта.

## Известные ограничения / что доделать

- Все обложки, превью и аватар — SVG-плейсхолдеры в `assets/img/placeholder/`; нет реальных
  фотографий/рендеров.
- `assets/files/placeholder-brandbook.pdf` — технический PDF-пустышка, чтобы ссылка и
  проверка ссылок проходили; реальный брендбук нужно положить сюда же или обновить путь.
- Блок `embed` в 3D-кейсе ссылается на `about:blank` (временно) и блок `video` не имеет
  реального файла/embed-ссылки — заменить на настоящее демо/видео, когда они будут готовы.
- `sketchfab`-блок использует `modelId: "PLACEHOLDER_MODEL_ID"` — заменить на реальный id
  модели после загрузки на Sketchfab.
- Картинки не ресайзятся/не конвертируются в WebP автоматически — для реальных фото нужно
  будет либо добавить обработку (Sharp и т.п.), либо готовить WebP+JPG вручную по схеме
  `renderImg()` в `build.js` (webp с тем же именем рядом с jpg/png).
- Нет сборки CSS/JS (бандлинга, минификации) — файлы отдаются как есть, это осознанно
  для каркаса.
- Дизайн (2026-10-11) — объединение макетов A и B из `_design/`, одна осознанно тёмная тема.
  Токены (цвета, шрифты, отступы, максимальные размеры капс-заголовков) — в `:root`
  файла `assets/css/style.css`. Шрифты Unbounded + Onest грузятся с Google Fonts (кириллица есть),
  без сети работает fallback-стек.
- Правило кадров: превью и работы показываются целиком в своих пропорциях (из `w`/`h`),
  раскадровка чередует широкие/горизонтальные/вертикальные кадры по этим пропорциям.
  Обрезка только в hero, шапке кейса и «следующем кейсе» — с `cover.focus`.
- Огромные капс-заголовки подгоняются под ширину экрана: `build.js` пишет в `--fit` длину
  самого длинного слова, CSS считает размер шрифта — горизонтального скролла не будет даже
  на 360 px.
- Бегущая строка клиентов строится из поля `client` кейсов (уникальные значения).
- Блок «Кто я» и страница «Обо мне»: тексты и таймлайн опыта — константа `ABOUT` в `build.js`
  (только факты из `../facts.md`, раздел «Резюме hh.uz»). Возраст считается при сборке из
  `BIRTH_DATE` в `build.js`; сама дата, телефон, зарплата на сайте не выводятся.
- Портреты: `assets/img/about/portrait-main-{800,1159}` и `portrait-alt-{800,1480}` (.webp + .jpg),
  ч/б дуотон, сделаны sharp из `../_work/portrait/` (фото 2 — по грудь, без руки; фото 1 —
  квадрат по лицу). Больше 1159/1480 px по ширине не делали, чтобы не апскейлить.
